# Master-branch join infrastructure contracts (for RadixHashJoin port)

Read on the working tree of branch `radix-join-bandwidth-model` (merge-base with `origin/master` = `2834291df98`).
All paths relative to `/mnt/ch/ClickHouse`. Line numbers are from the current working tree.

## 1. `src/Interpreters/IJoin.h` — the interface the port must implement

### No lane/slot-aware overloads exist on this tree
Unlike the donor branch, TODAY's `IJoin` has **no** lane-aware `addBlockToJoin`/`joinBlock`. The closest analogues:
- `addBlockToJoin(const Block &, bool check_limits)` — pure virtual, IJoin.h:101.
- `addBlockToJoin(const Block &, size_t num_rows, bool check_limits)` — virtual overload, IJoin.h:106-111. Added for CROSS joins where `Block::rows()` is 0 (PREWHERE consumed all columns). `FillingRightJoinSideTransform` calls THIS overload (JoiningTransform.cpp:373), so the port should override it or accept default forwarding.
- `HashJoin::addBlockToJoin(const Block &, ScatteredBlock::Selector, bool)` — non-virtual, HashJoin.h:146, "Called directly from ConcurrentJoin::addBlockToJoin". `HashJoin::joinScatteredBlock(ScatteredBlock)` — HashJoin.h:158. These are the selector-carrying entry points ConcurrentHashJoin uses per slot; a radix join can do the same (HashJoin-level, not IJoin-level).
- Stream-partitioned drain: `getNonJoinedBlocks(left_sample, result_sample, max_block_size, size_t stream_idx, size_t num_streams)` — IJoin.h:165-172. Default: stream 0 returns everything. This IS a slot-aware API present today.

### Key members (IJoin.h line refs)
- `JoinPipelineType` enum: 26-45 (`FillRightFirst` is what a radix join wants; default via `pipelineType()`:141).
- `IJoinResult` / `JoinResultPtr` (unique_ptr): 47-67. `JoinResultBlock { Block block; ScatteredBlock * next_block; bool is_last; }` (55-62). `next_block` is a back-pressure mechanism: when `is_last && next_block != nullptr`, the caller re-feeds the leftover rows as the next input chunk (see JoiningTransform.cpp:250-255 — calls `next_block->filterBySelector()` then puts the source block back into the input chunk). `IJoinResult::createFromBlock(Block)` helper: 66.
- `joinBlock(Block) -> JoinResultPtr`: 123. Contract comment: "Could be called from different threads in parallel". No stream index is passed — the join cannot tell which pipeline thread is calling.
- `initialize(const Block & left_sample_block)`: 117 — called once from `JoiningTransform::transformHeader` before the first joinBlock.
- `checkTypesOfKeys`: 119 (pure).
- `setTotals`/`getTotals`: 128-129; `getTotalRowCount`/`getTotalByteCount`: 132-133 (pure); `alwaysReturnsEmptySet`: 136 (pure).
- `isFilled`/`pipelineType`: 140-141; `supportParallelJoin`: 144 (return true to get parallel build).
- `getDelayedBlocks`/`hasDelayedBlocks`: 147-148 — the Grace-style drain hook (see §2).
- `getNonJoinedBlocks` (single-stream, pure): 150-151; `supportParallelNonJoinedBlocksProcessing`: 153; `isParallelNonJoinedProcessingEnabled`: 160 (runtime check, must be stable after `onBuildPhaseFinish` — comment 154-159 mentions `SpillingHashJoin` switching algorithms at runtime).
- `keepLeftPipelineInOrder`: 176 — called by `JoinStep` ctor when the plan needs left order preserved (JoinStep.cpp:126-127).
- `onBuildPhaseFinish`: 179 — called by `FillingRightJoinSideTransform` after ALL build data inserted; `hasPostBuildPhase`/`runPostBuildPhase`: 183-184 — optional extra step run in the same transform's next `work()` (timed under `ProfileEvents::JoinBuildPostProcessingMicroseconds`, JoiningTransform.cpp:357-362).
- `setEnableLazyColumnsIndexing`: 187.
- `clone`/`cloneNoParallel`/`isCloneSupported`: 79-97 (needed only for `joinPipelinesByShards`/YShaped; `ConcurrentHashJoin::isCloneSupported` requires empty state, ConcurrentHashJoin.h:85-88).
- `IBlocksStream`: 193-218. `next()` wraps `nextImpl()`; first empty block latches `finished` (atomic). Streams must tolerate concurrent `next()` only if the implementation itself locks (GraceHashJoin's `DelayedBlocks` does; see §2).

### Critical implicit contract: header-time joinBlock
`JoiningTransform::transformHeader` (JoiningTransform.cpp:30-39) runs at **pipeline build time**: `checkTypesOfKeys(header)`, `initialize(header)`, then `joinBlock(empty 0-row header block)` and uses `->next().block` as the output header. A new IJoin must return a correct-structure empty block from `joinBlock` before any build data exists and without side effects.

## 2. `src/Processors/Transforms/JoiningTransform.{h,cpp}` — probe path & drain

### Threading model
- One `JoiningTransform` per left stream (`num_streams` of them). `work()` runs on pipeline-executor threads; `joinBlock` is therefore called concurrently from up to `num_streams` threads, each transform holding its own `JoinResultPtr join_result` (JoiningTransform.h:83). No thread↔stream identity is guaranteed across work quanta.
- Each transform has a second input port with empty header connected to the build side; probe starts only after that port finishes (JoiningTransform.cpp:56-57, 107-118).
- `readExecute` (cpp:240-261): calls `join->joinBlock(block)` once per input chunk, then pumps `join_result->next()` one `JoinResultBlock` per `work()` call — this is the streaming/back-pressure quantum. If `is_last && next_block`, the leftover `ScatteredBlock` is converted back into the input chunk and joinBlock is called again on the next `work()`.
- `FinishCounter` (h:22-34): atomic fetch_add; `isLast()` true for exactly one caller.
- Non-joined (serial path): last `JoiningTransform` (via `finish_counter->isLast()`, cpp:161) calls the 3-arg `getNonJoinedBlocks` and drains it single-threaded (cpp:159-189). Skipped entirely when `supportParallelNonJoinedBlocksProcessing() && isParallelNonJoinedProcessingEnabled()` (cpp:126-134) — then `NonJoinedBlocksTransform` sources handle it.

### Build side: `FillingRightJoinSideTransform`
- h:95-117; cpp:263-405. One instance per right stream when `join->supportParallelJoin() && !right->hasTotals()` (see §6), each calling `join->addBlockToJoin(block, num_rows, true)` concurrently (cpp:373). `stop_reading` set when it returns false.
- Totals: `setTotals` called with an empty block even when there is no totals port (cpp:334-339) before finishing.
- **`onBuildPhaseFinish` semantics**: the LAST filling transform (shared `FinishCounter(max_streams)`) calls `join->onBuildPhaseFinish()` inside `prepare()` (cpp:341-349) — exactly once, single-threaded, with no concurrent IJoin calls (probe is still blocked on the signal port). If `hasPostBuildPhase()`, one more `work()` runs `runPostBuildPhase()` (cpp:355-362).
- Memory-pressure spill hooks: `getMemoryStats`/`spillOnSize` (cpp:379-405) — hard-wired `typeid_cast<GraceHashJoin *>`; `spillable` flag set the same way in the ctor (cpp:266). A radix join wanting scheduler-driven spilling must be added to these typeid checks.

### Grace-style drain (`DelayedJoinedBlocksTransform` + workers)
- `DelayedJoinedBlocksTransform` (h:138-153, cpp:536-602): a SINGLE processor with `num_streams` empty-header outputs, created iff `join->hasDelayedBlocks()` (QueryPipelineBuilder.cpp:534-536). Its `work()` calls `join->getDelayedBlocks()` (cpp:547) — serial, one bucket at a time. `prepare()` then broadcasts the SAME `IBlocksStreamPtr` (wrapped in `DelayedBlocksTask` chunk info with a fresh `FinishCounter(num_streams)`) to ALL outputs (cpp:585-599). It waits until every worker is idle (all outputs `canPush`) before fetching the next bucket (comment cpp:569-571). A null stream ends everything: an empty `DelayedBlocksTask` is broadcast and outputs finish (cpp:567-583).
- `DelayedJoinedBlocksWorkerTransform` (h:155-177, cpp:407-534): `num_streams` of them, each pulls the shared task and repeatedly calls `task->delayed_blocks->next()` — so **work stealing happens inside the shared IBlocksStream**, which must be internally synchronized. GraceHashJoin's `DelayedBlocks::nextImpl` (GraceHashJoin.cpp:~550-670) locks around a shared `left_reader.read()` and keeps a `not_processed_results` list under `extra_block_mutex`, plus an `eof_mutex` shared/exclusive handshake so the last reader doesn't drop in-flight leftovers (cpp:607-623).
- Right-side non-joined rows of the delayed bucket: only the worker for which `left_delayed_stream_finish_counter->isLast()` builds the non-joined stream via the `non_joined_stream_builder` lambda (cpp:518-534; lambda captures `join->getNonJoinedBlocks(left_header, output_header, max_block_size)`, QueryPipelineBuilder.cpp:585-588).
- `NonJoinedBlocksTransform` (h:180-204, cpp:604-644): `ISource` per stream calling the 5-arg `getNonJoinedBlocks(..., stream_index, num_streams)`; bails out if `isParallelNonJoinedProcessingEnabled()` is false at runtime (cpp:623).
- ProfileEvents used here (externs at cpp:10-20): `JoinBuildTableRowCount`, `JoinProbeTableRowCount`, `JoinResultRowCount`, `JoinNonJoinedTransform{Block,Row}Count`, `JoinDelayedJoinedTransform{Block,Row}Count`, `JoinBuildPostProcessingMicroseconds`.

## 3. `src/Planner/PlannerJoins.cpp` — algorithm selection

- `chooseJoinAlgorithm` (1367-1443): special cases first — StorageJoin (1384-1404), join-with-constant → requires `hash` (1409-1415), CROSS → plain `HashJoin` unconditionally (1422-1423), multiple OR disjuncts → requires `hash`/`auto` (1425-1426). Then iterates `table_join->getEnabledJoinAlgorithms()` (TableJoin.h:289) calling `tryCreateJoin` per algorithm, first non-null wins; throws `NOT_IMPLEMENTED` otherwise (1441-1442). **This is the fallback pattern**: a new algorithm should return nullptr from its `tryCreateJoin` branch when unsupported so iteration falls through.
- `tryCreateJoin` (1165-1313):
  - `HASH`/`PREFER_PARTIAL_MERGE`/`PARALLEL_HASH`/`DEFAULT` branch (1190-1245): builds `StatsCollectingParams{params.hash_table_key_hash, collect_hash_table_stats_during_joins, max_entries_for_hash_table_stats, max_size_to_preallocate_for_joins}` (1196-1200).
    - If `max_bytes_before_external_join > 0 && getTempDataOnDisk() && GraceHashJoin::isSupported` → `SpillingHashJoin` (concurrent-mode ctor with `params.max_threads` if `allowParallelHashJoin()` and the parallel-hash heuristic passes, 1202-1230).
    - Else if `table_join->allowParallelHashJoin()` and `use_parallel_hash` (`hash` not enabled OR no rhs estimation OR estimation >= `parallel_hash_join_threshold`, 1234-1235) → **`ConcurrentHashJoin(table_join, params.max_threads, right_header, stats_collecting_params)`** (1238) — slot count = `max_threads`.
    - Else plain `HashJoin` (1242-1244).
  - `GRACE_HASH` (1253-1270): throws if no temp storage configured; gated by `GraceHashJoin::isSupported` (no ASOF, INNER/LEFT/RIGHT/FULL, one disjunct — GraceHashJoin.cpp:303-308).
  - `AUTO` (1272-1310): SpillingHashJoin if external join configured, else `JoinSwitcher` or `HashJoin`.
- `allowParallelHashJoin` (TableJoin.cpp:1293-1307): PARALLEL_HASH in enabled algorithms, kind ∈ {Left, Inner, Right, Full}, not special storage, one disjunct. A new algorithm needs an analogous gate.
- `JoinAlgorithmParams` (1315-1365): two ctors — from `Context` (hash_table_key_hash = 0) and from `JoinSettings` (full). The real caller is `JoinStepLogical::buildPhysicalJoin` (src/Processors/QueryPlan/JoinStepLogical.cpp:1481-1507): computes `hash_table_key_hash = join_step->getRightHashTableCacheKey()` when stats collection is on, sets `rhs_size_estimation` from planner estimation or from `getHashTablesStatistics<HashJoinEntry>().getSizeHint(params)->source_rows` (1496-1506). `chooseJoinAlgorithm` is invoked at JoinStepLogical.cpp:1423.
- NOTE: the old analyzer has a **separate** static `chooseJoinAlgorithm` in src/Interpreters/ExpressionAnalyzer.cpp:1139 (called at 1293). A new algorithm reachable from the old analyzer needs changes there too; if only the new planner path is targeted, document that limitation.

## 4. `src/Interpreters/ConcurrentHashJoin.{h,cpp}` — build parallelism contract

- Ctor (cpp:181-244): `slots = toPowerOfTwo(min(slots_, 256))` (189). Per-slot `HashJoin` instances built in a private `ThreadPool` (191-197) with `ThreadGroupSwitcher(thread_group, ThreadName::CONCURRENT_JOIN)` (210) so allocations attach to the query's MemoryTracker; instance id `"concurrent{i}"`, `use_two_level_maps=true` (216-222). All slots share one `stored_columns_index` (234-236) so `RowRef::block_no` is globally unique.
- `addBlockToJoin` (cpp:289-354): called CONCURRENTLY by all `FillingRightJoinSideTransform`s (up to `max_streams`). Materializes once (293), scatters by right-key hash into `slots` `ScatteredBlock`s via `dispatchBlock` (295; selector = two-level bucket of the map's own hash `& (slots-1)`, cpp:564-578), then loops slots with `std::try_to_lock` on each slot's mutex, `std::this_thread::yield()` if no progress (305-349). Per-slot statistics-hint preallocation on first insert (`reserveSpaceInHashMaps`, 107-163, only its own `j % slots == i` buckets). Size limits checked over totals (351-353), lock-free totals via per-slot atomics (InternalHashJoin, h:108-118).
- `onBuildPhaseFinish` (cpp:756-928): merge phase — moves every slot's owned two-level buckets into slot 0's map (constant-time per bucket, 763-800), splices stored columns lists, consolidates right-side nullmaps into slot 0 (805-882), synchronizes `all_values_unique` (885-891), calls each slot's `HashJoin::onBuildPhaseFinish` (895-896), then copies the merged `maps` and a shared `used_flags` into every slot (898-925). Explicit contract comment (893): "`onBuildPhaseFinish` cannot be called concurrently with other IJoin methods".
- `joinBlock` (cpp:433-451): after merge (`twoLevelMapIsUsed()`), NO dispatch — the whole probe block goes against the shared map through slot 0 (`ConcurrentHashJoinResult`, 389-431). Before merge (single-level fallback), the probe block is scattered to slots and joined sequentially against each slot's map within one JoinResult. **Probe threads have no slot affinity.**
- `getNonJoinedBlocks` 5-arg (cpp:515-562): two-level → slot 0's map partitioned by `bucket % num_streams == stream_idx`; single-level → stream 0 concatenates per-slot streams (`ConcatStreams`, 356-387).
- `releaseSlotBlocks(slot_idx)` (h:74, cpp:744-754): extracts a slot's stored blocks (used by SpillingHashJoin slot conversion) — useful precedent for a radix join migrating data out.
- Dtor (cpp:246-287): parallel bucket destruction on the pool; also calls `updateStatistics` → `getHashTablesStatistics<HashJoinEntry>().update({ht_size, source_rows}, params)` (77-93) — this is how the size-hints cache gets fed.
- `SpillingHashJoin` (src/Interpreters/SpillingHashJoin.h:22-146) wraps HashJoin/ConcurrentHashJoin and switches to GraceHashJoin on memory overflow; `hasDelayedBlocks()` always true so the delayed transforms are always in the pipeline (returns nullptr from `getDelayedBlocks` if never spilled — instant finish). Same trick is available to a budget-bounded radix probe.

## 7. Cancellation, memory tracking, ProfileEvents

- **Cancellation**: NO cancellation hooks exist in IJoin/HashJoin/GraceHashJoin/SpillingHashJoin (verified by grep). Cancellation reaches joins only through the processor framework: `IProcessor::cancel(reason)` (IProcessor.h:268-270; IProcessor.cpp:80-91 calls virtual `onCancel()`); neither `JoiningTransform` nor `FillingRightJoinSideTransform` overrides `onCancel`, so cancellation takes effect **between `work()` quanta**. Consequences for the port: (a) keep each `IJoinResult::next()` call bounded (one output block) — the existing streaming JoinResult protocol is the cancellation granularity; (b) `GraceHashJoin::getDelayedBlocks` loads an ENTIRE bucket from disk inside one `DelayedJoinedBlocksTransform::work()` (GraceHashJoin.cpp:687-731) — not interruptible except via MemoryTracker exceptions; a budget-bounded probe should not make this worse. Memory-limit exceptions from the thread MemoryTracker are the only mid-work interruption mechanism.
- **MemoryTracker conventions**: in-memory join state is accounted implicitly via the querying thread's MemoryTracker (no explicit tracker objects in joins). Background pool threads must adopt the query's tracker via `ThreadGroupSwitcher(CurrentThread::getGroup(), ThreadName::...)` (ConcurrentHashJoin.cpp:208-210, 260-262). Disk spill buffers: create a child temp-data scope — GraceHashJoin.cpp:271-276: `tmp_data_->childScope({.current_metric = CurrentMetrics::TemporaryFilesForJoin, .bytes_compressed = ProfileEvents::ExternalJoinCompressedBytes, .bytes_uncompressed = ProfileEvents::ExternalJoinUncompressedBytes, .num_files = ProfileEvents::ExternalJoinWritePart}, table_join->temporaryFilesBufferSize(), table_join->temporaryFilesCodec())`; same pattern in TableJoin.cpp:1286-1290. Temp streams: `TemporaryBlockStreamHolder(sample_block, tmp_data)` (GraceHashJoin.cpp:415-416). Size-based decisions inside joins use `getTotalByteCount` snapshots, kept in relaxed atomics per slot for lock-free reads (ConcurrentHashJoin.h:114-117).
- **ProfileEvents pattern**: add `M(Name, "Doc string.", ValueType::Number|Bytes|Microseconds) \` to `APPLY_FOR_BUILTIN_EVENTS` in src/Common/ProfileEvents.cpp — the join block lives at ~415-428 (`JoinBuildTableRowCount` … `ConcurrentHashJoinProbeDispatchMicroseconds`; external-join events at 406-409). Consume via `namespace ProfileEvents { extern const Event Name; }` at the top of the TU (JoiningTransform.cpp:10-20) + `ProfileEvents::increment(...)` / `ProfileEventTimeIncrement<Microseconds> watch(...)` (JoiningTransform.cpp:359). CurrentMetrics likewise: `M(Name, "doc")` in src/Common/CurrentMetrics.cpp (`TemporaryFilesForJoin`:55, `ConcurrentHashJoinPoolThreads*` referenced at ConcurrentHashJoin.cpp:65-70).

## 8. Porting checklist implied by the above

1. Implement `IJoin` with: 2-arg AND 3-arg `addBlockToJoin`, `joinBlock` returning a streaming `IJoinResult` (empty-block/header-time safe), `checkTypesOfKeys`, `initialize`, totals, row/byte counters, `alwaysReturnsEmptySet`, both `getNonJoinedBlocks` overloads, `supportParallelJoin() = true` for parallel build.
2. `onBuildPhaseFinish` runs once, single-threaded, before any probe — do partition finalization there; long CPU-bound finalization can go to `hasPostBuildPhase`/`runPostBuildPhase` (but note both run in ONE thread of `FillingRightJoinSideTransform`).
3. For a streaming budget-bounded probe with spilled partitions, reuse the delayed-blocks machinery: return true from `hasDelayedBlocks`, hand out one internally-synchronized `IBlocksStream` per partition from `getDelayedBlocks`; all `num_streams` workers will pull from it concurrently (GraceHashJoin::DelayedBlocks is the reference implementation including the eof_mutex leftover-handshake).
4. There is no per-thread lane/slot identity anywhere in the probe path on this tree — any lane-aware donor API must be either dropped (dispatch internally by hash, like ConcurrentHashJoin) or emulated via the shared-stream work-stealing model.
