Verdict: **clean**. The fix is minimal and correctly shaped; findings below are minor.

## Lens 1 — Reduce complexity

**R1. Loop form: simplest correct form — keep.**
A plain two-accumulator range-for is the established shape for exactly this aggregation in
this code family: `updateStatistics` in `src/Interpreters/ConcurrentHashJoin.cpp` (lines
76-84) sums `rows_to_join` across the slots the same way, and this very file already has two
`total_map_bytes` loops of identical form (lines 163-165, 237-239). An
`std::accumulate`/fold would be less idiomatic here, not simpler. Summing both terms and
dividing once (rather than averaging per-slot ratios) is the correct whole-join semantics —
the commit does the right thing.

**R2. No existing helper is a substitute.**
`HashJoin::getTotalByteCount` includes `nullmaps_allocated_size` and hash-table buffer bytes,
so reusing it would change the estimate. Direct field sums are the right primitive.

**R3. Should it live elsewhere — flag, not demand.**
Both inputs are build-time quantities, constant across the probe; this loop now makes the
*third* per-probe-block O(slots) pass over `slot_joins` aggregating build-side constants in
the routed path (the two `total_map_bytes` loops plus this one). The stated later unit that
hoists this once-per-build is the right home and should consolidate all three into one
per-build slot-fleet summary. One note for that unit: `allocated_size` is adjusted after
insertion by the shrink-to-fit paths (`src/Interpreters/HashJoin/HashJoin.cpp`, ~line 867),
so the snapshot must be taken at/after `onBuildPhaseFinish`, not mid-build. For now,
per-block recomputation is a few dozen pointer chases per probe block — negligible; do not
block on the hoist.

**R4. Optional: name the ratio.**
`total_allocated_size / std::max<size_t>(1, total_rows_to_join)` sits inline as the 6th of
11 positional arguments in the `HashJoinResult::Properties` brace initializer. A named local
(`avg_joined_bytes_per_row`, mirroring the `Properties` field it feeds) would self-document
the argument. Counterpoint: the inline expression exactly mirrors the non-routed path
(`src/Interpreters/HashJoin/HashJoinMethodsImpl.h:212`), and that symmetry aids diffing the
two paths. Since the hoist unit will restructure this anyway, not worth churn now.
