# Reduce-complexity review: 561c1d21b99 + aa98041d472 (u3)

Scope: `src/` changes of both commits, reviewed together. Lens is non-behavioral
simplification only — the fold contract, the flat walk semantics (wrap-aware walk,
zero-key detour, discard semantics for non-cursor families) and all green gates are
frozen. Every suggestion below preserves the instantiation set and the emitted find
logic; none changes behavior.

Verdict: the hoist itself is clean (the plan genuinely deletes three per-block O(slots)
passes and the per-block `SlotMapDesc` rebuild). What accreted is parameter/knob
redundancy around the seams: one dead local, one fully redundant lambda template
parameter, and a couple of collapsible macro/lambda wrappers.

---

## 1. `maps_data` is a dead alias of the `maps_by_slot` parameter

- **Location:** `src/Interpreters/HashJoin/HashJoinRoutedMethodsImpl.h:276`
  (`const Map * const * maps_data = maps_by_slot;`), comment at lines 273–275.
- **What:** Before commit 1 this local was a real snapshot (`maps_by_slot.data()` of a
  vector, hoisted so the loop bodies' opaque `appendFromBlock` calls don't force
  reloads). After the hoist, `maps_by_slot` is already a raw pointer parameter — a
  local with identical aliasing properties — so `maps_data` is a pure rename. The
  comment above it ("Snapshots of the plan's arrays") is now only accurate for
  `flags_data` and `flat_descs`; `maps_by_slot` is not a plan array in this scope.
- **Why non-behavioral:** deleting a `T x = y;` where `x` and `y` are interchangeable
  locals; codegen-identical.
- **Suggested change:** drop `maps_data`, use `maps_by_slot` directly (7 use sites),
  and reword the comment to cover only the two real snapshots (`flags_data`,
  `flat_descs`).

## 2. The `flat_find` lambda template parameter is redundant with the trait

- **Location:** `src/Interpreters/HashJoin/HashJoinRoutedMethodsImpl.h:335` (lambda
  signature), 397–423 (nested `if constexpr`), 630–647 (dispatch).
- **What:** The only dispatch that reaches the non-`precomputed` arm passes
  `flat = flat_lookup_supported<KeyGetter, Map>` — a compile-time constant of the
  enclosing template's types. So `flat_find` never carries information the inner
  trait check doesn't already have: for flat-capable families the plain-`findKey`
  arm is discarded in every instantiation, for the rest the flat arm is discarded in
  every instantiation. The `precomputed = true` instantiations discard the whole
  `else` branch regardless of `flat_find`'s value. The parameter is a knob with one
  position.
- **Why non-behavioral:** replacing `if constexpr (flat_find) { if constexpr (trait) A } else B`
  with `if constexpr (trait) A else B` yields the same instantiated body for every
  (family, shape) pair. The discard semantics are preserved: the code's own comment
  (lines 397–401) states the INNER trait check is what keeps the flat arm out of the
  non-cursor families' instantiations — the outer `flat_find` check contributes
  nothing to that. Under [stmt.if]/2, during instantiation of the enclosing
  `joinRightColumns` the trait condition is non-value-dependent, so the false arm is
  not instantiated for non-cursor maps — exactly what the current inner check
  provides.
- **Suggested change:** remove the `flat_find` parameter and the `constexpr bool flat`
  at the dispatch (reverting the four call sites to their pre-commit-2 shape); keep a
  single `if constexpr (flat_lookup_supported<KeyGetter, Map>)`. Keep a one-line
  version of the WHY comment on the surviving check: "the trait is dependent at this
  template's definition, so the flat arm (which needs `grower_type::tail_pad` and the
  cursor cell contract) is never instantiated for non-cursor families".
- **Follow-on (optional):** with the nesting gone, the `handle` continuation lambda
  (line 388) can also disappear by producing `find_result` from an immediately-invoked
  `ALWAYS_INLINE` lambda (trait arm: zero-key detour or `flatFindKey`; else arm:
  `key_getter.findKey`) and restoring the original single
  `if (find_result.isFound()) { ... }` block. Both arms return the same
  `KeyGetter::FindResult` by value; codegen-identical. This restores the pre-change
  loop-body shape with the find swapped, which is the minimal diff the change needed.

## 3. `maps_by_slot` as a threaded parameter next to `plan` — fold into a typed accessor

- **Location:** `src/Interpreters/HashJoin/HashJoinRoutedMethodsImpl.h:120` (the
  blessed `reinterpret_cast`), `HashJoinRoutedMethods.h:56,68` (signatures),
  `HashJoinRoutedMethodsImpl.h:145,238` (parameters).
- **What:** The typed pointer array is derived from `plan.map_by_slot.data()` and then
  threaded alongside `plan` through two more signatures, so the innermost layers
  receive the same object twice (once erased inside `plan`, once typed). It does earn
  *some* place — the cast must happen where `Map` is known — but the cast site need
  not be the switch: both consumers (`joinRightColumnsRouted`, `joinRightColumns`)
  have `Map` as a template parameter, and they are only ever reached through the
  switch that erased the pointers, so the "same switch, exact cast" invariant is a
  type-level fact, not a call-site fact.
- **Why non-behavioral:** same cast, same pointers, moved to a named single location.
- **Suggested change:** give `RoutedProbePlan` a typed view, e.g.
  `template <typename Map> const Map * const * mapsBySlot() const` (carrying the
  "this cast is exact because the map-type switch chose `Map`" comment and the
  `chassert`), and drop the `maps_by_slot` parameter from `joinRightColumnsRouted`
  and `joinRightColumns`. Shrinks two signatures and removes the double-carry.
  Judgment call: keeping the cast textually adjacent to the switch is also
  defensible — but then at least hoist the `chassert(plan.map_by_slot.size() ==
  slot_joins.size())` and its comment out of the `M` macro body (they don't depend on
  `TYPE`; one line above the switch instead of once per case, and the macro shrinks).

## 4. `collectRoutedProbePlan`: hoist the invariant lambda, drop the wrapper

- **Location:** `src/Interpreters/ConcurrentHashJoin.cpp:264–287`.
- **What:** `collect_map` captures only `plan` and `type` — both loop-invariant — yet
  is re-defined inside the per-slot loop, and is then invoked through a second wrapper
  lambda: `std::visit([&](auto & maps) { collect_map(maps); }, ...)`. Also,
  `join.getJoinedData()` is called three times per slot (lines 261, 262, 287).
- **Why non-behavioral:** lambda hoisting and passing `collect_map` directly to
  `std::visit` (it is already a generic callable of the right shape); a hoisted
  `const auto & joined = *join.getJoinedData();` local is a pure CSE.
- **Suggested change:** define `collect_map` once before the loop;
  `std::visit(collect_map, joined.maps.at(0));` per slot. Optional micro-tidy:
  `plan.chain_may_wrap = plan.chain_may_wrap || ...` → `|=`. The switch itself is
  fine as-is: it follows the codebase's idiomatic `APPLY_FOR_JOIN_VARIANTS(M)`
  pattern (cf. `getTotalByteCountImpl` in `HashJoin.cpp`), the `requires` clause is
  the right gate for the cursor-only members, and the enum has no members outside
  the macro (no EMPTY/CROSS on this branch), so no default arm is missing.

## 5. `slot_joins` threads two layers deep for one always-true bit (optional)

- **Location:** `src/Interpreters/HashJoin/HashJoinRoutedMethodsImpl.h:296`
  (`slot_joins[0]->amacEnabled()`); `slot_joins` parameters at
  `HashJoinRoutedMethods.h:53,65`.
- **What:** After commit 1, `joinRightColumnsRouted` only forwards `slot_joins`, and
  `joinRightColumns` reads exactly one thing from it: `slot_joins[0]->amacEnabled()`.
  That bit is set once (`setAmacEnabled(true)`, `ConcurrentHashJoin.cpp:213`) before
  either plan collection runs, and `joinRoutedBlock`'s only caller is
  `ConcurrentHashJoin` — so it is a per-build constant that naturally belongs in the
  plan next to `chain_may_wrap` (also a per-build engagement bit).
- **Why non-behavioral:** the plan is collected after `setAmacEnabled`; both
  collection points observe the same value the probe reads today.
- **Suggested change (optional):** add `amac_enabled` to `RoutedProbePlan` and drop
  `slot_joins` from `joinRightColumnsRouted`/`joinRightColumns` (with finding 3 this
  leaves those signatures carrying `plan` as the single per-build argument). Fine to
  skip if the team prefers `amacEnabled` to stay visibly a `HashJoin` property.

## 8. Duplication: `flatFindKey` vs the ring's step (flag only, per instructions)

Three copies of the home-cell address expression
`static_cast<const Cell *>(desc.buf) + (hash & desc.mask)` now exist:
`AmacProbe.cpp` (`start`, ~line 184), `HashJoinRoutedMethodsImpl.h:215`
(`flatFindKey`) and `:322` (prefetcher flat arm). The zero-key synchronous detour
(key-holder → `isZeroKey` via map 0 → map-resolved find) is likewise spelled both in
the ring's `start` and in the loop's flat arm. The walks themselves should NOT be
unified: the ring's step is resumable, one-cell-per-visit and deliberately wrap-free
(gated by `chain_may_wrap`), while `flatFindKey` is synchronous and wrap-aware — the
difference is the design. The safely shareable piece is a tiny
`SlotMapDesc`-adjacent helper for the home-cell address (e.g.
`template <typename Cell> const Cell * homeCell(size_t hash) const`), trivially
inlined, no perf risk. Flagging only; not demanded.

## Not findings (checked and fine)

- The double collection (constructor + `onBuildPhaseFinish`) is not redundancy: the
  constructor pass exists so plan-time header probes hit sized arrays (the `chassert`
  at the switch), and the rebuild-into-a-local-then-move keeps re-collection clean.
- `RoutedJoinResult` taking `plan` as a constructor argument alongside `parent`
  mirrors the pre-existing `slot_joins` pattern (it cannot reach the private member
  through `parent` without friendship); consistent, leave.
- `plan.map_by_slot` (type-erased) plus `desc_by_slot` (buf/mask) is not double
  storage: the descriptor exists precisely so the hot path avoids the map header,
  while the map pointer serves functors and the zero-key/fallback finds.
- The `switchJoinRightColumns` switch is exhaustive over `HashJoin::Type` (the enum
  is exactly `APPLY_FOR_JOIN_VARIANTS`); no dead default needed.

## Summary

Two commits with a sound structural core and a modest amount of seam cruft: one dead
alias local (`maps_data`), one one-position template knob (`flat_find`) whose removal
also lets the loop body return to its original shape, a double-carried map array that
can become a typed plan accessor, and a hoistable lambda/chassert pair in the
collector. All suggestions are codegen-neutral or instantiation-set-neutral; gates
(parity 636, order, gtests) should be re-run after any of them as routine, not
because behavior is expected to move.
