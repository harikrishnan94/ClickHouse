## High value — stale docs the commits should have updated

### H1. `AmacProbe.h:156-158` — "All 64 instantiations" is now 160, and the axis list is stale twice over
Both commits edited the macro directly under this comment and neither updated it. Commit 1
took the set from 64 to 80 (adding `MapsAsof`, whose mapped type is neither `RowRef` nor
`RowRefList`), commit 2 doubled it to 160 (walk axis) — the commit message even says
"80 -> 160" while the comment still says 64. This is the single loudest "nobody re-read the
surroundings" tell in the diff.
Current: `All 64 instantiations: 8 families x {RowRef, RowRefList} mapped x flagged-or-not x {range, indexes} selector.`
Suggested: `All 160 instantiations: 8 families x {MapsOne, MapsAll, MapsAsof} (both flag arms where flags exist; ASOF is never flagged) x {range, indexes} selector x {bare, wrap-aware} walk. Any (kind, strictness) resolves to a preinstantiated symbol.`

### H2. `AmacProbeImpl.h:24-26` — class doc actively contradicts commit 1
The `AmacFindPolicy` doc still says the result is "the matched cell's mapped value copied by
value into `found_word` (... see `amac_mapped_fits_word` in `AmacProbe.h` for why the copy,
not a pointer, is recorded)". Since commit 1, ASOF records precisely a pointer
(`recordedWordOf`, `amac_mapped_by_pointer`). "why the copy, not a pointer" is now wrong for
one of the shapes the policy serves.
Suggested: "... the matched cell's recorded word - the mapped value by value, or its address
for ASOF (see `amac_mapped_fits_word` / `amac_mapped_by_pointer` in `AmacProbe.h`) - and, ...".

### H3. `AmacProbeImpl.h:35-38` — class doc still describes the pre-commit-2 world
Same doc block: "The collision walk is a bare `++cell` - no mask, no bound check: ... the
engagement gate verified that no chain reached a buffer's last cell". Commit 2 removed the
gate's `!plan.chain_may_wrap` guard and made the walk a template policy; the in-`step` comment
was updated ("the plan verified ...") but this paragraph was not. A reader of the class doc
does not learn the policy has a `walk` axis at all.
Suggested: "The collision walk is `++cell`; under `AmacWalk::bare` there is no mask and no
bound check (the plan verified no chain reached a buffer's last pad cell), under
`AmacWalk::wrap_aware` it wraps at the pad end like the grower's `next`."

### H4. `AmacProbe.h:100-108` — `amacFindPass` contract doc missed the ASOF case
"`found_word[i]` is the matched cell's mapped value copied BY VALUE (0 = no match; ...)".
Stale since commit 1 for `MapsAsof`. Suggested: "... is the matched cell's recorded word (by
value for the word-sized mapped types, the mapped value's address for ASOF; 0 = no match; ...)".

### H5. `AmacProbe.h` — after the split, nothing in the header says where the body went
The lens question "does `AmacProbe.h` still describe what moved?" — mostly yes (the module doc
at lines 14-20 survived the move because it was duplicated into the new file), but the reader

## Naming

### N1. `AmacProbe.h:85-89` — `AmacWalk::bare` / `AmacWalk::wrap_aware` break the module's enum casing
The immediate siblings are `AmacMode::{Off, Auto, Force}` and `AmacStepResult::{Advance, Done,
DoneNeedsGrow}` — CamelCase values. Snake_case enumerators here read like a different author.
Suggested: `AmacWalk::Bare` / `AmacWalk::WrapAware` (and update the four use sites plus the
20-line macro table).

### N2. `AmacProbe.h:85` — `enum class AmacWalk : bool`
The only `enum class ... : bool` under `src/`; the module uses `UInt8` (`AmacStepResult`,
`RouteColumnKind`) or nothing (`AmacMode`). `bool` as an underlying type for a two-value policy
is clever but foreign. Suggested: drop the underlying type or use `UInt8`.

### N3. `AmacProbeImpl.h:236` — "the slot lane" collides with the file family's other "lane"
In this same probe path "lane" already means the thread lane of the pooled scratch
(`HashJoinRoutedMethodsImpl.h:568`, `PoolParksAndReusesPerLane` gtests). The ring's own doc
calls its members "parallel arrays". Suggested: "the ring's `slot` entry recovers the bounds
from the descriptor table". (The commit message uses "the ring's slot lane" too.)

### N4. `AmacProbeImpl.h:19` — `namespace AmacProbeDetail`
House norm for an implementation namespace is plain `namespace detail` nested in `DB` (63
files, including `Interpreters/`); the prefixed form has a single precedent
(`FunctionsLogicalDetail`). Acceptable, but `detail` would read more native. Low severity.

Not findings: the new gtest suite `AmacWrappedWalk` matches its file name, which follows the
`JoinSlotRouting` precedent; `ConcurrentHashJoinAmacAsof` fits the sibling suites. Allman
braces are correct throughout `AmacProbeImpl.h`, `gtest_amac_wrapped_walk.cpp`, and the new
dispatch lambda. No `f()`-style references in the new text.

## Tone / phrasing
