# HUMANIZE review — 96136264c16 ("Pool the routed probe's scratch per pipeline lane")

Report-only. Scope: `src/` changes only (tmp/ evidence ignored). Line numbers refer to the
files as of 96136264c16. All suggestions are non-behavioral (comments, naming, wording).

Overall: mechanically clean — Allman throughout, `f`-not-`f()` respected, backticks correct in

### 2. The pool-fallback contract is stated five times
- **Locations:**
  - `src/Interpreters/ConcurrentHashJoin.cpp:293-294` (`releaseProbeScratch` body): "a
    collision (or an out-of-range lane) falls through to the pool, so the scratch is never
    lost and never double-owned"
  - `src/Interpreters/ConcurrentHashJoin.h:101-103` (`invalid_lane` doc): "lanes outside the
    parking table (or the lane-less legacy entry points) fall back to the mutexed pool, so
    lane collisions and out-of-range indices stay correct, just slower"
  - `src/Interpreters/ConcurrentHashJoin.h:140-142` (`probe_scratch_slots` doc): "misses go
    through the pool"
  - `src/Interpreters/IJoin.h:127-128`: "joins must tolerate out-of-range and colliding lanes"
  - `src/Interpreters/tests/gtest_concurrent_hash_join_amac.cpp:692-693`: "the mutexed pool
    absorbing collisions and out-of-range lanes"
  ("never lost and never double-owned" also appears verbatim in the commit message.)
- **What:** The `IJoin.h` statement is the contract (right place, different audience) and the
  member doc's "misses go through the pool" is terse enough — but the `invalid_lane` doc and
  the `releaseProbeScratch` comment each re-narrate the full fallback story. Verbatim
  restatement of one fact at every site that touches it is a generated-text tell; the earlier
  hygiene passes on this branch established the one-statement precedent.
- **Suggested rewording:** Keep the full statement once, on the member `probe_scratch_slots`
  (it already carries the acquire/release protocol). Trim `invalid_lane` to: "Lane value used
  by the lane-less `joinBlock` entry points; always takes the mutexed pool path." Trim the
  `releaseProbeScratch` comment to the local non-obvious bit: "A collision or an out-of-range
  lane falls through to the pool."

### 3. "steady state allocates nothing per block" stated four times
- **Locations:**
  - `src/Interpreters/HashJoin/JoinProbeScratch.h:9-10` (struct doc): "pooled on the join and
    reused across probe blocks so the steady state allocates nothing per block"
  - `src/Interpreters/ConcurrentHashJoin.cpp:519-520` (`joinBlock` body): "the steady state
    reuses its capacity across blocks, so nothing here allocates per block after warm-up"
  - `src/Interpreters/HashJoin/HashJoinRoutedMethodsImpl.h:511-513`: "The arrays live in the
    lane's pooled scratch: `resize` never shrinks a `PaddedPODArray`, so the steady state
    reuses the capacity across blocks"
  - the commit message ("the steady state allocates nothing per probe block")
- **What:** Same motivation restated wherever the scratch is touched. The struct doc is the
  right home; the `HashJoinRoutedMethodsImpl.h` site carries one load-bearing local fact
  (`resize` never shrinks), the `joinBlock` site carries none.
- **Suggested rewording:** Keep `JoinProbeScratch.h` as is. In `HashJoinRoutedMethodsImpl.h`
  keep only the local fact: "The arrays live in the lane's pooled scratch; `resize` never
  shrinks a `PaddedPODArray`, so the capacity survives across blocks." In `joinBlock` drop the
  comment entirely — `acquireProbeScratch(lane)` next to a documented struct needs no caption.

### 4. `probe_scratch_slots` overloads "slot", the class's most loaded word
- **Location:** `src/Interpreters/ConcurrentHashJoin.h:144` (and its uses in
  `ConcurrentHashJoin.cpp`)
- **What:** Everywhere else in this class "slot" means a hash-join shard: `slots`,
  `slot_joins`, `slot_ids`, `getNumSlots`, `releaseSlotBlocks`, `computeDispatchSlotIds`. The
  new member is indexed by *lane* (pipeline stream), a completely different axis — and it is
  even sized `2 * slots`, so `probe_scratch_slots.size() != slots`, inviting exactly the
  confusion the name creates. A maintainer steeped in this file would not reuse the word.
- **Suggested rewording:** `probe_scratch_by_lane` (or `lane_scratch`); the comment then no
  longer needs "the parking table" as a third name for the same thing (it is called "slot",
  "parking table", and "lane's slot" across the diff — pick one).

### 5. `lane` vs `stream_index` — one concept, two names across the seam
- **Locations:** `src/Interpreters/IJoin.h:125` / `ConcurrentHashJoin.{h,cpp}` (`lane`) vs
  `src/Processors/Transforms/JoiningTransform.h:89` (`stream_index`),
  `src/QueryPipeline/QueryPipelineBuilder.cpp:601` (`/*stream_index_=*/i`)
- **What:** The transform passes `stream_index` into a parameter every other file calls
  `lane`; "lane" is also new vocabulary in this part of the codebase (its existing `src/` uses
  are SIMD lanes). The split is defensible (transforms speak "streams"), but the
  `JoiningTransform` member comment then has to translate: "probe lane index, passed to
  `IJoin::joinBlock`...".
- **Suggested rewording:** Either rename the transform member to `lane` to match the interface
  it feeds, or keep `stream_index` everywhere and let `IJoin::joinBlock` name the parameter
  `stream_index` too. One word for one concept.

### 6. Caps-for-emphasis cluster
- **Locations:**
  - `src/Interpreters/HashJoin/JoinProbeScratch.h:12`: "copied BY VALUE"
  - `src/Interpreters/IJoin.h:126`: "are NOT guaranteed"
  - `src/Interpreters/tests/gtest_concurrent_hash_join_amac.cpp:680`: "of the SAME lane"
  - `src/Interpreters/tests/gtest_concurrent_hash_join_amac.cpp:728`: "must NOT observe"
- **What:** Four shouted words in one diff. Occasional "NOT" appears in the surrounding branch
  code, but "BY VALUE" and "SAME" push it into tic territory.
- **Suggested rewording:** Lowercase all four; the sentences carry the emphasis already
  ("copied by value", "two acquisitions of the same lane", "a fresh acquisition must not
  observe the in-flight scratch").

### 7. Gtest comment tone: coinages, ellipsis, defensive preamble
- **Locations:** `src/Interpreters/tests/gtest_concurrent_hash_join_amac.cpp:691-694, 680-681,
  733-735`
- **What:**
  - "These tests pin the ownership contract, not performance." — declaring what the tests
    *don't* test is preamble a human wouldn't write; the test bodies make it obvious.
  - "Two concurrent-in-time acquisitions" — "concurrent-in-time" is a coinage; "legally
    collide" anthropomorphizes.
  - "The result destructor runs at scope exit and parks the scratch... unless the slot is
    occupied by the release above, in which case it goes to the pool - either way it is
    recoverable below." — the trailing-off ellipsis is chatty narration.
- **Suggested rewording:** Drop the "pin the contract, not performance" sentence. "Two
  overlapping acquisitions of the same lane (the totals transform and stream 0 both use lane
  0) must return two distinct live scratches." "The destructor parks the scratch at scope
  exit — into the lane slot, or into the pool if the release above occupied it; either way it
  is recoverable below."
